RL Environments · License or custom build

Did the agent make a real database cheaper to run?

Most RL environments for coding agents check whether the agent produced the right answer. Mine check something harder. The agent gets a slow SQL query, its own copy of the database and a shell, and has to tune the query.

It is scored on logical reads: how many database pages the query really touches. Not wall-clock time, which mostly measures the machine. Not how clean the execution plan looks, which is what the engine intends to do, not what it does.

The task sits where an environment is useful for training: frontier models succeed sometimes, but not reliably.

Explore the environment Request a demo under NDA

Graded on what the database did

Logical reads are what a DBA tunes for on a shared server. In one batch, the two "obvious" join indexes made the query almost 4× more expensive than adding no indexes at all, while the execution plan looked better.

A gradient, not a cliff

The reward is monotonic: every page saved raises the score, so a model gets a learning signal instead of a pass/fail cliff. Scores spread from 0.24 to 1.0, and the same submission always gets the same score.

Hard to game

Grading happens in a clean room on a fresh copy of the database, so shortcuts that lower the page count without tuning anything don't pay. Every rule the prompt states, the grader enforces.

Built on Prime Intellect's verifiers framework, running in a pinned, offline-capable Docker image. SQLite keeps the demo small and self-contained, but nothing in the approach is SQLite-specific. PostgreSQL and Oracle are next.
